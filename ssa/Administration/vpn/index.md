
### Левый:

ок:
```
router ospf 1

network 189.132.32.0 0.0.15.255 area 0 // локальная сеть
network 189.132.64.0 0.0.15.255 area 0 // туннель
```

статика
```
ip route 0.0.0.0 0.0.0.0 189.132.17.2 // маршрут по умолчанию на следующий хоп
```

туннель
```
interface Tunnel0
 ip address 189.132.64.1 255.255.240.0 // должен быть в одной сети с другим
 tunnel source Serial0/1/0 // выход в интернет
 tunnel destination 189.132.17.6 // адрес марша, в сеть которого мы доставляем, который смотрит в интернет
```


### Правый:

ospf:
```
router ospf 1
 network 189.132.48.0 0.0.15.255 area 0 // локалка
 network 189.132.64.0 0.0.15.255 area 0 // туннель
```

статика
```
ip route 0.0.0.0 0.0.0.0 189.132.17.5 // адрес соседнего марша из интернета
```

туннель
```
interface Tunnel0
 ip address 189.132.64.2 255.255.240.0 // в одной сети пон да
 tunnel source Serial0/1/1 // интернет кабель соседа или чей хуй знает
 tunnel destination 189.132.17.1 // адрес марша,в сеть которого мы доставляем, который смотрит в интернет
```


Настройка туннеля GRE

1: данные передаются по туннелю используя ipv4 адреса и транспортным протоколом тоже являеются ipv4 адреса
```
int tunnel 0
 tunnel mode gre ip
```

2: по туннелю данные передаются по ipv6 адресу. транспортным протоколом являются ipv4 адрес
```
int tunnel 0
 ipv6 add 2001::1/64
 tunnel mode ipv6ip
 tunnel source [ipv4]
 tunnel destination [ipv4]
```


3: транспортом являются ipv6 адреса
```
int tunnel 0
 ipv6 add 2001::1/64
 tunnel mode ipv6ip
 tunnel source [ipv6]
 tunnel destination [ipv6]
```

## 1. Введение в VPN (Virtual Private Network)

**VPN** — это технология создания защищенного «туннеля» поверх общедоступной сети (обычно Интернета). Она позволяет объединять удаленные офисы и сотрудников в единую частную сеть.

### Ключевые преимущества:

- **Экономия:** Использование обычного Интернета вместо дорогих выделенных линий.
    
- **Масштабируемость:** Легкое добавление новых узлов без смены физической инфраструктуры.
    
- **Безопасность:** Защита данных с помощью шифрования и строгой аутентификации (например, IPsec).
    
- **Гибкость:** Поддержка различных технологий доступа (DSL, оптика, мобильные сети).
    

---

## 2. Типы VPN-соединений

| **Тип VPN**                          | **Описание**                                                                           | **Применение**                                                       |
| ------------------------------------ | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **Site-to-Site (Узел-Узел)**         | Постоянное соединение двух шлюзов. Внутренние узлы не знают о существовании VPN.       | Соединение филиалов с главным офисом.                                |
| **Remote Access (Удаленный доступ)** | Динамическое соединение. Клиент (ноутбук/смартфон) подключается к серверу.             | Работа удаленных сотрудников через клиентское ПО (Cisco AnyConnect). |
| **DMVPN (Dynamic Multipo int)**      | Технология Cisco для динамического создания туннелей между филиалами (Spoke-to-Spoke). | Масштабируемые корпоративные сети со сложной топологией.             |

---

## 3. Протокол GRE (Generic Routing Encapsulation)

**GRE** — это базовый протокол туннелирования, разработанный Cisco. Он создает виртуальный канал «точка-точка» поверх IP-сети.

### Характеристики:

- **Инкапсуляция:** Позволяет передавать трафик разных протоколов (IPv4, IPv6, AppleTalk, IPX) и **Multicast** (что критично для протоколов маршрутизации вроде OSPF/EIGRP).
    
- **Безопасность:** По умолчанию **не поддерживает шифрование**.
    
- **Заголовок:** Добавляет минимум 24 байта служебной информации.
    
- **Идентификатор:** В поле протокола IP используется значение `47`.
    

---

## 4. Настройка GRE на оборудовании Cisco

Для создания туннеля необходимо настроить виртуальный интерфейс `Tunnel` на обоих маршрутизаторах.

### Алгоритм настройки (на примере R1):

1. Создать туннельный интерфейс.
    
2. Назначить IP-адрес (из внутренней частной сети).
    
3. Указать источник (физический IP своего внешнего интерфейса).
    
4. Указать назначение (внешний IP удаленного маршрутизатора).
    

Bash

```
R1(config)# interface tunnel 0
R1(config-if)# ip address 10.0.0.1 255.255.255.252
R1(config-if)# tunnel source 209.165.201.1
R1(config-if)# tunnel destination 198.51.100.2
R1(config-if)# tunnel mode gre ip (опционально, так как это режим по умолчанию)
```

## 5. Проверка и устранение неполадок

### Основные команды проверки:

- **Проверка статуса интерфейса:**
    
    Bash
    
    ```
    show ip interface brief
    ```
    
    _(Статус должен быть up/up)_.
    
- **Проверка параметров туннеля и инкапсуляции:**
    
    Bash
    
    ```
    show interface tunnel 0
    ```
    
- **Проверка работы маршрутизации через туннель:**
    
    Bash
    
    ```
    show ip ospf neighbor
    show ip route
    ```
    

### Частые ошибки:

1. **Несовпадение адресов:** IP-адреса туннельных интерфейсов должны быть в одной подсети.
    
2. **Маршрутизация:** Отсутствие маршрута до `tunnel destination` (внешнего адреса соседа).
    
3. **MTU:** Проблемы с фрагментацией пакетов из-за дополнительного заголовка GRE (24 байта).
    
4. **ACL:** Межсетевой экран блокирует протокол GRE (IP 47).

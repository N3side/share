По умолчанию в Cisco IOS есть 2 уровня доступа к командам:

- **Пользовательский режим (уровень привилегий 1).** Обеспечивает самые низкие привилегии ввода и позволяет писать только команды пользовательского уровня

- **Привилегированный режим (уровень привилегий 15).** Включает все команды уровня enable

- все что между 1 и 15 - кастомные настройки

Ограничения:

- Не обеспечивается управление доступом к определенным интерфейсам, портам, логическим интерфейсам и слотам на маршрутизаторе.

- Команды, доступные на нижних уровнях привилегий, всегда выполняются на более высоких уровнях.

- Команды, для которых специально задан более высокий уровень привилегий, недоступны для пользователей с более низкими привилегиями.

-  Присвоение команды с несколькими ключевыми словами открывает доступ ко всем командам, использующим эти ключевые слова. Например, разрешив доступ к команде **show ip route,** вы открываете доступ пользователю ко всем командам **show** и **show ip** .


```
privilege exec level [level] [command]

например 
privilege exec level 5 ping // типа до 5 уровня включительно можно писать эту комманду

username Ivan privilege 5 secret lol

enable [еще можно указать тип шифрования algorithm-type script] secret level 5 123 // создать общий пароль для входа а этот уровень
```

Чтобы перейти в уровень пишем

```
enable [уровень]
```

### Система представлений

Корневое представление нужно для:
- конфигурации других представлений.
- Корневое представление имеет те же привилегии доступа, что и привилигированный режим. Отличие - только внутри корня можно конфигурировать другие представления

### Отличия представления от уровней привилегий

- дает доступ к определенным интерфейсам портам, лог. интерфейсам
- не имеет иерархии команд
- нет наследования команд
- можно более точно настроить доступ к командам

### 3. Как создать Суперпредставление (Superview)

Допустим, хотим создать вид `SUPER_BOSS`, который объединяет `MY_VIEW` и еще один вид `ADMIN_VIEW` (который мы предположим уже создали).

```
! Убедись, что ты в Root View (если нет: enable view)

! Создаем СУПЕРвид (обязательно слово superview в конце)
parser view SUPER_BOSS superview

! Задаем пароль для супервида
secret superpass

! Добавляем созданные ранее обычные виды внутрь этого супервида
view MY_VIEW
view ADMIN_VIEW

! Выходим
exit
```

Теперь, если кто-то войдет в `SUPER_BOSS`, он получит доступ ко всем командам из `MY_VIEW` И из `ADMIN_VIEW`.

### Аутентификация протокола маршрутизации

Спуфинг - это вид атаки, при которой злоумышленник маскируется под доверенный источник, подделывая идентификационные данные. 
Спуфинг может использоваться для:
- Перенаправления трафика для создания петель маршрутизации
- Перенаправления трафика, так чтобы его можно было видеть в незащищенном канале

Чтобы избежать спуфинга, маршрутизаторы передают зашифрованную таблицу маршрутизации другим, у которых настроено шифрование

md5 уязвима перед атаками, лучше использовать sha


#### шифрование через md5:

```
router ospf 1
 area 0 authentication message-digest
exit

interface Gi0/0
 ip ospf message-digest-key 1 md5 [password]
exit
```


#### шифрование через sha

```
key chain OSPF_KEYS
 key 1
  key-string CISCO123_SHA
  cryptographic-algorithm hmac-sha-256
 exit
exit

interface Gi0/0
 ip ospf authentication key-chain OSPF_KEYS
exit
```

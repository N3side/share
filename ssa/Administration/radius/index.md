сеть должна спроектирована так, чтобы была возможность контролировать кому и когда разрешено к ней подключаться и что разрешено в ней делать

aaa создает необходимую структуру для масштабируемой защиты доступа

без aaa любой с паролем может все поменять, нельзя отслеживать и управлять доступом

authentication authorization accounting (введение учета, аудит)

Авторизация: какие права у этого пользователя, т.е, что он может делать на этом марше или коммуте, а он записывает действия пользователя, когда он вошел, вышел, какими командами пользовался.

Аутентификация без aaa неудобная т.к без нее любой может войти в аккаунт и сложно управлять доступом.

### Режимы аутентификация:

- Локальная аутентификация
- серверная аутентификация

---
### Локальная:

достоинства:

- просто
- дешевле
- подходит для маленьких сетей

Отличия от серверной, что логины и пароли хранятся на каждом устройстве индивидуально

Недостатки:

- нужно настраивать на любом устройстве
- не подходит для больших сетей

### Серверная аутентификация

логины и пароли хранятся на сервере. При подключении к устройству, устройство каждый раз спрашивает разрешение у сервера

плюсы:
- удобно управлять
- масштабируется
- все в одном месте

минусы:
- сложнее настроить

По правильному авторизацию и учет лучше реализовывать на базе сервера, т.к не надо выделять память на каждом оборудовании для контроля для того чтобы настроить AAA:

```
aaa new-model
aaa authentication login [default] local
// в line vty login local не надо писать, только transport input all
```

### Команды для настройки серверной аутентификации:

```
aaa new-model

radius server [имя на него вообще поебать]
 address ipv4 192.168.1.100 auth-port 1812 acct-port 1913
 key [password]uz,g,g
 
 
aaa authentication login default group radius local
```

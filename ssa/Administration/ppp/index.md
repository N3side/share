
### Глава 2  
  
Соединение точка-точка  
  
Одним из самых распространенных подключений в глобальной сети для связи на больших расстояниях явялется подключение точка-точка которые еще называются последовательным соединением или подключение по выделенным линиям.  
  
пример  
  
- последовательная связь  
- параллельная (не используют потому что медные кабелы влияют друг на друга (скручивают друг друга))  
  
Протоколы инкапсуляции  в глобальной сети:  
  
### HDLC  
  
ЭТО ТИП инкапсуляции по умолчанию на всем оборудовании cisco оно включено по умолчанию. но есть ограничения:  
  
- это однопротокольный протокол (он передает только либо ipv4, либо ipv6)  
  
### PPP (point-to-point)  
  
обеспечаивает соединение типа маршрутизатор - маршрутизатор (R - R) и узел - сеть. т.е м-у маршами или м-у компами. ppp работает по синхронным и ассинхронным каналами с несколькими протоколами сетевого уровня ipv4 & 6. ppp основан на протоколе инкапсуляции HDLC. Также имеет встроенные механизмы защиты аутентификации PAP и CHAP.  
  
Остальные протоколы:  
  
- протокол последовательной межсетевой связи (SLIP)  
- X 25/ процедура сбалансированного доступа к каналу (LAPB)  
- Frame relay (устаревший)  
- ATM  
  
инкапсуляция HDLC  
  
- cisco hdlc  
- еще один  
  
Кадр hdlc состоит из  
- флага (флаг), обозначающий начало и конец кадра  
- адрес (широковещательный)  
- поля управления FCS обрабатывает ошибки и уведломяет.  
- поле данные это пакет сетевого ур-я, где указаны сами данные ip адреса и т.д  
  
### Настройка HDLC  
  

int s 0/0/0  
encapsulation hdlc  
  
// проверка:  
sh ip [int]

  
  
если м-у маршрутизаторами используются gi то это хуйня потому что они не для инкапсуляции  
  
  
### Альтернативный протокол PPP  
  
это протокол канального уровня, который состоит из 3 компонентов  
- семейство сетевых управляющих протоколов (NCP) 
- LCP
- инкапсуляция
  
он схож с сетевым уровнем и настраивает протоколы сетевого уровня (ipv4 || ipv6)  
  
  
### Протокол управления канала передачи LCP  
  
устанавливает, настраивает и тестирует соединение (сюда же относится аутентификация)  
  
  
### Кадрирование  
  
Формат кадра PPP схож с **HDLC**, но есть отличия. PPP использует физическую среду передачи данных.

отличия: 
- имеется поле протокол
  

### Преимущества PPP  
  
- функция управления качеством связи (LQM), которое позволяет контролировать качество связи. зайти надо в интерфейс сериал и написать команду  
  

ppp quality [percentage]  

  
  
Если процент ошибки падает ниже установленного порогового значения канал связи отключается а пакеты переправляются, или отбрасываются (если альтернативных путей нет)  
  
Кадр ppp схож с кадром HDLC. Отличия:  
  
- имеется поле "протокол", где опредеделяется протокол полезной нагрузки PPP.
  
### Дополнительные функции PPP  
  
- аутентификация PAP | CHAP  
- сжатие данных с использованием Stacker или Predictor  
- Многоканальность (похож на etherchannel), только в глобальной сети. Объединяет несколько каналов и увеличает пропускную способность  
  
  
### Команды  
  
(на обоих маршрутизаторах)  

hostname //надо если аутентификация нужна  
```
int [int]  
 no ip add  
 encapsulation ppp  
compress [predictor | stac] // необязательная команда  
pp quality [percentage] // nullable
```
  

  
  
### Многоканальность команды  

```
int Multiling 1  
 // ip add  
 // ipv6 add  
 ip add [nonegotiated/свой ip]

 ppp multiling

```

```
int [int]

```


**Firewall (межсетевой экран)** — устройство для защиты внутренней сети от внешних сетей (интернет), которое решает, какой трафик пропускать, а какой — нет
## Типы межсетевых экранов (МЭ)

### Пакетный фильтр (Packet Filtering)

Уровень работы: Сетевой (3) и Транспортный (4)

| Принцип работы | Фильтрация по заголовкам пакетов: IP-адрес, порт, протокол |
|---------------|-----------------------------------------------------------|
| ✅ Преимущества | • Простота настройки<br>• Высокая скорость работы |
| ❌ Недостатки | • Уязвим к IP-спуфингу<br>• Проблемы с фрагментированными пакетами (последующие фрагменты могут пройти без проверки)<br>• Не сохраняет состояние соединения (каждый пакет проверяется отдельно)<br>• Плохо работает с динамическими портами<br>• Сложные правила требуют высокой квалификации |

> ⚠️ MTU = 1500 байт: если пакет >1500 байт, он делится на фрагменты. Первый фрагмент проверяется, последующие могут пройти без проверки.

### 2. МЭ с сохранением состояния (Stateful Firewall)
Уровень работы: Сетевой, Транспортный, Сеансовый (3–5)

| Принцип работы | Запоминает состояние соединений, различает новые запросы и ответы, анализирует весь сеанс связи |
|---------------|------------------------------------------------------------------------------------------------|
| ✅ Преимущества | • Хорошая производительность<br>• Защита от атак (DoS, спуфинг)<br>• Распознаёт подозрительные подключения<br>• Подробное логирование<br>• Видит контекст сетевого взаимодействия |
| ❌ Недостатки | • Не анализирует содержимое данных (payload)<br>• Сложности с UDP/ICMP<br>• Проблемы с динамическими портами<br>• Не поддерживает аутентификацию пользователей |

---

### 3. Шлюз прикладного уровня (Proxy Server)
Уровень работы: Все уровни, включая Прикладной (7)

| Принцип работы | МЭ выступает посредником: клиент → МЭ → сервер. Сервер не видит реальный IP клиента. Проверка данных на уровне приложений. |
|---------------|--------------------------------------------------------------------------------------------------------------------------|
| ✅ Преимущества | • Глубокий контроль трафика (DPI)<br>• Полная анонимизация клиента<br>• Кэширование контента |
| ❌ Недостатки | • Ниже производительность из-за глубокой проверки<br>• Сложнее в настройке |

## 🔹 Дополнительные типы реализации МЭ

| Тип | Описание |
|-----|----------|
| Хостовый МЭ | ПО устанавливается на сервер или ПК (персональный фаервол) |
| Прозрачный МЭ | Работает на канальном уровне (мост), фильтрует трафик без изменения IP-адресации |
| Гибридный МЭ | Сочетает пакетную фильтрацию, stateful-инспекцию и прокси (например, Cisco ASA) |

## 🔹 Cisco ASA: Внедрение многофункциональной защиты

### Модели ASA
| Модель | Сценарий | Скорость | Особенности |
|--------|----------|----------|-------------|
| ASA 5505 | Малый офис | до 150 Мбит/с | Компактная, для небольших сетей |
| ASA 5506 | Средний бизнес | до 750 Мбит/с | Баланс цены и производительности |
| ASA 5512/5515 | Крупный бизнес, ЦОД | 1/2/4 Гбит/с | Много интерфейсов, поддержка больших потоков и VPN |

### Расширенная функциональность

1. Виртуализация (Security Contexts)  
   → Один физический ASA делится на несколько логических МЭ с отдельными правилами, интерфейсами и администраторами.

2. Кластеризация (Active/Passive)  
   → Два идентичных ASA для отказоустойчивости.

3. Идентификация пользователей  
   → Интеграция с AD: правила строятся по пользователям, а не по IP.

4. Сервисы контроля угроз  
   → IPS, антивирус, защита от вредоносного контента.

## 🔹 Зоны безопасности в ASA

| Зона    | Уровень безопасности | Описание                      | Правила трафика                                  |
| ------- | -------------------- | ----------------------------- | ------------------------------------------------ |
| inside  | 100                  | Внутренняя защищённая сеть    | → outside: ✅ разрешено<br>→ DMZ: ✅ разрешено     |
| outside | 0                    | Внешняя сеть (Интернет)       | → inside: ❌ запрещено<br>→ DMZ: ⚠️ выборочно     |
| DMZ     | 50 (промежуточный)   | Публичные сервера (web, mail) | → inside: ❌ запрещено<br>→ outside: ⚠️ выборочно |


> 📌 Правило по умолчанию: трафик разрешён из зоны с более высоким уровнем безопасности в зону с более низким.

## 🔹 Режимы работы ASA

| Режим | Описание | Особенности |
|-------|----------|-------------|
| Маршрутизируемый (Routed) | Работа на 3-м уровне, каждый интерфейс — отдельная подсеть | Поддерживает: NAT, VPN, динамическую маршрутизацию |
| Прозрачный (Transparent) | Работа на 2-м уровне (как мост), фильтрация без изменения IP | Не поддерживает: VPN, DHCP-сервер, маршрутизацию |
